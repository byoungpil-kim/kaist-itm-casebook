# ITM 사례연구 기사 작성 가이드 (v2 — 확정 스타일)

## 목적
KAIST ITM 졸업 사례연구(20~60쪽 논문형 보고서)를 아산기업가정신리뷰(AER) 스타일의
매거진형 웹 기사로 변환한다. **원저자가 "내 보고서를 잘 요약했다"고 느껴야 한다.**

## 절대 규칙 (사용자 피드백 반영)
1. **원문 목차 구조와 목차 제목을 가급적 유지**하면서 요약한다. 임의로 전혀 다른 구성의
   글로 재창작하지 말 것. 장(章) 제목은 원문 표현을 그대로 또는 살짝 줄여서 사용한다.
   - 예: 원문 "제5장 연구 결과 > 5.1 암묵지의 형식지화" → 기사 h2 "5. 연구 결과: ..." h3 "5.1 암묵지의 형식지화"
   - 서론/이론적 배경/산업 분석/사례 분석/연구 결과/결론 및 시사점 등 원문의 장 흐름을 따른다.
   - 분량이 적은 장(이론적 배경 등)은 하나의 h2 아래 h3들로 압축 가능. 완전히 생략하지 말고
     최소 1-2문단으로라도 다룬다.
2. **소제목·본문에 원문의 표현을 가급적 살린다.** AI식 재작성 문구("~의 비밀", "~가 던진 질문" 남발) 금지.
   풀쿼트(pull quote)는 원문에 실제로 있는 문장(또는 최소한으로 다듬은 문장)을 사용한다.
3. 길이: 한국어 기준 약 1,500~2,500단어 분량의 HTML. 지금 샘플 수준 또는 약간 더 길게.
4. 사실 왜곡 금지: 수치·연도·고유명사는 반드시 원문에서 그대로 가져온다. 원문에 없는
   내용을 지어내지 않는다.

## 출력 파일
`/home/claude/cases_src/{id}_body.html` — 페이지 본문 조각(fragment)만 작성.
(<html>, <head>, 헤더/푸터 없음. 빌드 스크립트가 감싼다.)

## 프래그먼트 구조 (순서 고정)
```html
<p class="lead">리드문 2-4문장: 사례의 핵심 사실과 연구가 답하려는 질문. 원문 서론/초록 기반.</p>

<div class="keybox">
  <div class="kb-title">연구 요약</div>
  <ul>
    <li><b>연구 질문:</b> 원문의 연구질문을 그대로/압축해서</li>
    <li><b>핵심 발견/성공요인:</b> ...</li>
    <li>(3~5개 항목, 원문 초록·결론 기반)</li>
  </ul>
</div>

<h2>원문 장 제목</h2>   <!-- 원문 목차 순서대로 3~6개의 h2 -->
<h3>원문 절 제목</h3>   <!-- 필요시 -->
<p>...요약 본문...</p>

<div class="pull">원문에서 뽑은 인상적인 문장 (기사 전체에 1~2개)</div>

<figure>
  <img src="../assets/img/{id}/{파일명}.png" alt="그림 설명">
  <figcaption><b>&lt;그림 N&gt; 원문 캡션.</b> 부연 설명. (출처: 원문 표기 출처)</figcaption>
</figure>
<!-- 그림/표 이미지 3~4장을 본문 흐름에 맞는 위치에 배치 -->

<h2>결론 및 시사점(원문 제목 사용)</h2>
<div class="insight">
  <div class="in-title">결론 및 시사점</div>
  <ul>
    <li><b>요점:</b> 원문 결론의 시사점을 3~4개 항목으로</li>
  </ul>
</div>
```

## 그림 선택 방법
1. `/home/claude/imgpool/{id}/` 의 PNG들이 원문에서 추출된 그림·표 이미지다. 파일명 `f-PPP-NNN.png`의
   PPP는 PDF 페이지 번호. 본문 텍스트에서 <그림 N>/<표 N> 위치(원문 쪽번호)와 대조해 후보를 고른다.
2. 후보 이미지를 Read 도구로 열어 실제 내용을 **눈으로 확인**한 뒤 3~4장을 고른다.
   - 좋은 그림: 핵심 데이터 차트, 프레임워크/모델 다이어그램, 비교표, 연대표
   - 피할 것: 표지, 저자 사진, 단순 로고, 화질 낮은 스크린샷, 내용 판독 불가 이미지
3. 선택한 이미지를 `mkdir -p /home/claude/website/assets/img/{id}/ && cp ...` 로 복사한다.
4. figure의 src는 반드시 `../assets/img/{id}/파일명.png`.
5. 이미지가 전혀 쓸 만하지 않으면(판독불가 등) figure 0~2장도 허용. 대신 표 데이터를
   HTML <table>로 재구성해도 좋다(원문 수치 그대로).

## 원문 읽기
- 텍스트: `/home/claude/website/extract/{id}.txt` (pdftotext -layout 결과, 쪽 구분 \f)
- 스캔본(텍스트 없음)인 경우: imgpool의 페이지 이미지를 Read로 열어 내용을 파악한다.
- 메타데이터(제목·저자·지도교수·기업·분야): `/home/claude/website/assets/meta.json`에서 해당 id 참조.

## 문체
- 경어체가 아닌 평서문("~했다", "~이다"). 기사체이되 원문의 학술적 정확성 유지.
- 이론 용어는 원문 표기 그대로(예: 파괴적 혁신(Disruptive Innovation), 흡수역량, SECI 모델).
- 과장·홍보 문구 금지. 원문이 제시한 한계·리스크도 있으면 언급.

## 완성 기준 체크리스트
- [ ] h2/h3 제목이 원문 목차 제목과 대응하는가
- [ ] 풀쿼트가 원문 문장 기반인가
- [ ] 수치·연도·이름이 원문과 일치하는가
- [ ] 이미지 3~4장이 website/assets/img/{id}/에 복사됐고 src 경로가 맞는가
- [ ] keybox(연구 요약)와 insight(결론 및 시사점)가 있는가
